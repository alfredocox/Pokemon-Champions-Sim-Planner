Data Sources

This page shows what the sim actually reads from each outside source, what is only used as a cross-check, and how source drift is detected before trust claims are made.

Truth policy
Pokemon Showdown is the main upstream baseline for species data, move metadata, learnsets, target categories, and generated runtime legality assets. Champion-specific regulation differences stay separate as reviewed overrides or source-review rows until they are tested and promoted. User imports, replay logs, and QA artifacts are evidence inputs, not source truth.

Pokemon Showdown data
GitHub/CDN upstream baseline		 Species stats, typings, abilities, move metadata, priority, target categories, learnsets, species weights, sprite slugs, and generated legality/runtime assets. Not the final word on Champion-only regulation differences unless the repo has accepted that behavior for the current lane. Showdown sync workflow, generated asset rebuilds, priority drift tests, runtime bridge tests, move support audits, and approved entity review.
Champion rules / regulation sources
Ruleset-specific source review		 Regulation windows, allowed roster deltas, Champion-only policy differences, and whether a lane is review-only or playable. Not a direct replacement for the engine or generated Showdown legality data without explicit conversion and tests. Ruleset registry, review-only sections, conversion rows, legality gating, and Overview release notes.
Victory Road
Competitive event context		 Current regulation dates, event usage context, image-sheet roster review, and source-review discovery for new legal roster slices. Not the live battle calculator and not enough on its own to promote runtime legality. Manual source-review cards, Reg M-B review rows, and promotion gates before selectors or coaching can trust the data.
Bulbapedia
Mechanics citation layer		 Move, item, ability, terrain, weather, and status behavior citations when static data does not fully explain the resolution rule. Not a generated runtime asset source and not used as a raw import feed. Targeted engine tests, mechanics audit cases, turn-log evidence, and source notes in code/docs when behavior is claimed fixed.
@smogon/calc / Showdown oracle slices
Behavior cross-check		 Selected damage and mechanic parity proofs where static rows alone are not enough. Not the full live engine and not a substitute for Champion-specific override review. Oracle tests, damage parity slices, move verification registry, and named release proof for the exact mechanic audited.
Smogon format/meta pages
Cross-check and meta context		 Import/export conventions, archetype language, and current competitive context for team-review notes. Not the primary legality calculator for Champion data and not the source of damage logic. Manual review, archetype catalog updates, and explicit notes when a page is contextual rather than authoritative.
Supabase approved rows
Reviewed storage layer		 Approved teams, approved Showdown entities, overrides, audits, and saved analysis history. Not the browser damage calculator and not trusted automatically just because a row exists in DB. Approved views, runtime DB inspector, source hashes, approved counts, seed parity checks, and local-vs-live drift review.
User imports / replays / QA artifacts
Evidence tier		 Testing inputs, replay review, retained proof, coaching evidence, and bug reproduction artifacts. Not upstream source truth and not trusted meta data until validated against legal/runtime gates. Turn-log validator, QA artifact schema, build/source labels, retained evidence counts, and targeted proof checks.
What changes should trigger a review?
  • Showdown updates move priority, target type, recoil/drain data, learnsets, species stats, typings, or abilities.
  • Champion regulation windows, legal roster rules, or Champion-only mechanics guidance change.
  • Victory Road or equivalent source-review sheets add new legal roster rows or event-usage context.
  • Approved DB rows no longer match generated assets, seeded teams, or live browser selectors.
  • QA artifacts expose a mechanic the source matrix says is trusted, but the replay evidence disagrees.
Release watch and game news
This section is the user-facing reminder of which outside changes matter. If one of these changes lands upstream, the simulator should treat it as a release-note event and update the relevant rules, data, tests, QA proof, and Overview notes together.
Change type What users should expect us to update
Regulation / format update Allowed species/forms/items/mechanics, team legality lanes, team filters, source-review cards, and current testing catalog.
Move or ability behavior update Engine logic, move support registry, targeted mechanics tests, QA proof teams, replay evidence wording, and coaching trust level.
Meta shift or tournament trend change Testing catalog priorities, matchup proof teams, strategy notes, and which archetypes we stress first. This should not silently rewrite legality truth.
Source conflict between trusted sites Overview gap note, explicit temporary policy, blocked promotion if needed, and a named follow-up issue until the conflict is resolved.
DB/source drift Generated assets, seed SQL, approved DB rows, live selectors, and browser QA artifacts must be re-aligned before the change is treated as shipped truth.

Bundled teams may come from official tournament results, community pastes, or maintained local reconstructions. Custom imports and local simulations are separate evidence tiers, not official event records.
