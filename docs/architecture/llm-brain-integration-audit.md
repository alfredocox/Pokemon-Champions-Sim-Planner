# LLM Brain Integration Audit

Date: 2026-07-05
Branch: `analysis/llm-brain-audit`
Base checked: latest `origin/main` at audit start
Scope: documentation-only Phase 0 audit for an evidence-backed LLM Brain analyst layer.

## Executive Summary

The repository is ready for a safe LLM Brain foundation, but not for real LLM calls yet.

The existing app already has strong deterministic truth boundaries:

- `engine.js` owns battle mechanics and produces structured turn evidence.
- generated Showdown data plus `runtime_data.js` own static Pokemon/move/species access.
- `move_legality.js`, `legality.js`, `team_lab.js`, and `legality_evidence_package.js` own legality and source-gated team trust.
- replay/QA exports already carry `damage_events`, `effect_events`, claim boundaries, QA readiness, and production-readiness gate data.
- Supabase is an optional persistence/audit layer with local-only fallback; it is not the battle calculator.

The safest LLM Brain path is therefore:

```text
deterministic simulator/replay/source evidence
  -> browser-safe analysis evidence bundle
  -> deterministic analysis tools
  -> no-API Brain Composer and validator
  -> UI cards
  -> local feedback and improvement packs
  -> optional DB persistence later
  -> feature-flagged external LLM endpoint later
```

Phase 1 should not touch battle mechanics, release identity, Supabase credentials, generated bundles, or public AI calls. It should create the evidence-bundle schema and tests only.

## 1. Current Simulator Source-Of-Truth Boundaries

### Battle Mechanics

Primary owner:

- `poke-sim/engine.js`

Observed responsibilities:

- validates in-engine team shape with `validateTeam`
- constructs Pokemon runtime state
- resolves speed, priority, turn order, Trick Room, Tailwind, and action execution
- resolves targeting, damage, recoil, drain, HP costs, recovery, status, field effects, item/ability hooks, switching, faint cleanup, and win conditions
- exports `simulateBattle`, turn logs, `positionScore`, `winProbabilityDelta`, and battle helper surfaces through `window.ChampionsSim`

Important LLM boundary:

- The LLM Brain must never calculate damage, decide legality, alter RNG, select priority order, or replace `simulateBattle`.

## 7. Risks And Unknowns

1. `ui.js` contains many useful analysis helpers but is too large and UI-coupled for direct reuse.
   - Mitigation: Phase 2 should create wrappers/stubs first, then gradually extract pure functions only when tests prove parity.

2. There are already coaching and learning surfaces, but they are not an LLM evidence contract.
   - Mitigation: Evidence bundles should wrap current outputs without implying model authority.

3. Real LLM calls from GitHub Pages would expose secrets if done directly.
   - Mitigation: real model mode must wait for a feature-flagged endpoint such as Supabase Edge Function or another server-side proxy.

4. Supabase has local fallback and trusted-writer boundaries.
   - Mitigation: Brain persistence must follow existing adapter patterns and remain optional.

5. Regulation M-B legality remains evidence-gated.
   - Mitigation: Brain recommendations must carry legality status and source gaps; unknown legality cannot become a recommended legal change.

6. Damage and move-mechanics proof is still not universal.
   - Mitigation: Brain confidence must degrade when QA artifacts report missing targeted proof or partial mechanic-family proof.

7. Generated/offline bundle support is a release constraint.
   - Mitigation: browser Brain modules must be deterministic, bundle-safe, and compatible with no-network mode until an explicit LLM endpoint is enabled.

8. Prompt injection via replay uploads or team text is a future risk.
   - Mitigation: model prompts must be generated from validated evidence bundles, not raw user text.

## 8. Exact Next Implementation Tasks

### Milestone A - Safe Foundation

1. Create `poke-sim/analysis/schemas.js`.
   - Define `ANALYSIS_TYPES`, `EVIDENCE_CATEGORIES`, and confidence levels.
   - Export browser-safe and Node-compatible API.

2. Create `poke-sim/analysis/confidence.js`.
   - Provide confidence validation and simple downgrade helpers for uncertainty/source gaps.

3. Create `poke-sim/analysis/provenance.js`.
   - Normalize `source_tool`, `source_version`, `source_file`, `source_id`, and optional evidence pointers.

4. Create `poke-sim/analysis/evidence_bundle.js`.
   - Implement `createEvidenceBundle(input)`, `addFinding(bundle, finding)`, `validateEvidenceBundle(bundle)`, and `collectEvidenceIds(bundle)`.
   - Require every finding to include `id`, `category`, `claim`, `confidence_prior`, `evidence`, and `provenance`.

5. Add Node tests under `poke-sim/tests/analysis/evidence_bundle_tests.js`.
   - Cover valid bundle, invalid analysis type, invalid category, missing finding fields, duplicate IDs, missing provenance, missing confidence, and uncertainty handling.

6. Do not add LLM calls, UI cards, Supabase writes, or release bumps in Milestone A.

### Milestone A Follow-Up - Deterministic Tool Contracts

7. Add conservative tool stubs under `poke-sim/analysis/tools/`.
   - `validate_team_analysis.js`
   - `speed_tiers.js`
   - `damage_matrix.js`
   - `threat_detection.js`
   - `lead_recommendations.js`
   - `role_coverage.js`
   - `replay_summary.js`
   - `index.js`

8. Each tool should return evidence findings plus uncertainty, not free-form advice.

9. Start by wrapping existing deterministic facts:
   - legality status from validators
   - speed estimates or logged speed order
   - damage rows already emitted by the engine
   - replay parser findings and source gaps

10. Keep all high-confidence output tied to deterministic data and sample-size/source context.

### Later Milestones

11. Draft DB evidence tables only after bundle schema tests pass.
12. Add Brain output schema, local rules, local templates, no-API composer, and validator before any real LLM endpoint.
13. Add local feedback and improvement-pack export before DB-backed learning.
14. Add benchmarks before treating Brain output as release-safe.
15. Add UI cards only after validator rejects fake evidence IDs and unsupported claims.
16. Add real LLM endpoint only behind disabled-by-default flags and server-side key storage.
